# ADR-0001：真站對照的範圍與基準

- 狀態：Accepted
- 日期：2026-10-04

## 背景

本專案是「Mocking momoshop」的前端 take-home。考核點包含「實作結果與真實網站的差異」與「Validation / Observability 思維」，但 Phase 2 之前只有三張真站截圖與 worklog 的敘述式對照，沒有結構化、可追溯的對照基準，也沒有定義「像」要在哪些面向上成立。真站會持續改版，若不固定基準，對照結果無法重現。

## 決策

1. **對照軸只取四個**：功能有無、骨架版面、互動流程、RWD。
2. **視覺細節與資料真實度為非目標**：配色、字級、圖片素材、商品與分類的真實度一律不比對、不列為缺口，在 `docs/parity.md` 中以 tradeoff 的身分出現。
3. **基準為 2026-10-04 的一次性快照**：真站截圖存 `docs/momo-ref/*-20261004.jpeg`，對照結果存 `docs/parity.md`。真站之後改版不觸發 mock 修改，除非另立 ADR。
4. **觀察手段限制為少量瀏覽器觀察**：以 Playwright 開啟四頁、讀 DOM 與互動狀態、截圖；不批量爬取、不登入、不保存真站 HTML。
5. **缺口只記錄不補**：對照發現的缺口列入 `docs/parity.md`「未來工作」，不佔用 Phase 2 剩餘時間。

## 後果

- 面試官可以用同一份矩陣看出哪些差異是決策、哪些是簡化、哪些是缺口，差異不再散落在 README 與 worklog。
- 「像不像」有了可重現的判準，後續任何功能修改都能對照同一份基準更新狀態。
- 代價是基準會過時：2026-10-04 之後真站的變動不會反映在文件裡，文件標題與每張截圖檔名都帶日期以提醒讀者。
- 視覺與資料兩個面向不會被評估，若之後的需求轉向視覺還原，需要新的 ADR 推翻本決策第 2 點。
