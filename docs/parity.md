# 真站對照評估（Parity Matrix）

> 回答考核點「實作結果與真實網站的差異」與「Validation / Observability 思維」。
> 以 **2026-10-04** 的 momo 購物網為一次性基準快照，不追蹤後續改版（決策見 [ADR-0001](adr/0001-parity-scope-and-baseline.md)）。

## 基準與方法

| 項目 | 內容 |
|---|---|
| 真站入口 | `https://www.momoshop.com.tw/main/Main.jsp`、`/search/:keyword`、`/product/:id`、`/discover` |
| 觀察手段 | Playwright 開啟真站四頁，讀 DOM 結構與互動狀態、截圖；不批量爬取、不登入 |
| 視口 | 桌機 1280×900、手機 390×844（真站現為單一 RWD 站，未導向 m 站） |
| 範圍 | 首頁、搜尋結果頁、商品頁、發現頁，加「加入購物車」跨頁互動。真站購物車／結帳需登入，不在範圍 |
| 比對軸 | 功能有無、骨架版面、互動流程、RWD |
| 非目標 | 視覺細節（配色、字級、圖片素材）與資料真實度（商品、價格、分類樹）。這兩項列為 tradeoff，不視為缺口 |
| 真站截圖 | `docs/momo-ref/momo-{home,search,goods,discover}-{1280,390}-20261004.jpeg` |
| mock 截圖 | `docs/checks/task13-*.jpeg`（當日同版本） |

## 狀態詞彙

| 狀態 | 意義 |
|---|---|
| **一致** | 行為與版面位置相同（視覺細節不計） |
| **簡化** | 有做，但範圍縮小；說明欄寫明縮在哪 |
| **刻意省略** | 決策不做，對應 `docs/design.md` §2／§9 的 tradeoff |
| **缺口** | 這次對照才確認、有時間會補的項目；只記錄不補 |
| **超出** | mock 有而真站沒有，或 mock 行為比真站完整 |

## 未來工作（缺口清單，本次只記錄不補）

依對使用者旅程的影響排序：

1. **手機底部 tab bar**（#8／F18）：390 下真站的主要導覽與購物車入口，mock 完全沒有對應物。
2. **搜尋結果 390 無限捲動**（#26／F9）：真站在手機放棄分頁；mock 沿用桌機分頁，`worklog` Task 8 已列為演進方向。
3. **Hero 觸控滑動**（F5）：手機上輪播只能等自動播放或點圓點。
4. **捲動後 header 收合**（#6／F19）：影響手機可視區域。

這些若要推進，依 `docs/agents/issue-tracker.md` 開 issue 並以 `docs/agents/triage-labels.md` 標記；不在本次 Phase 2 時間內處理。

## 刻意省略與簡化的依據

- 範圍決策（結帳、會員、直播、mobile drawer、SSR）：`docs/design.md` §2「刻意不做」與 §9 Tradeoff 總表。
- Variant 單一維度、不影響價格庫存：`CONTEXT.md`「Variant（規格）」。
- 視覺細節與資料真實度為非目標：[ADR-0001](adr/0001-parity-scope-and-baseline.md)。
